# 需求澄清与异常降级

## 需求澄清

- 四要素：对象、范围、用途、验收。缺一个先问，不派活。
- 一次问完，2–4 个问题，带推荐选项，不问开放题。
- 派活写精确路径与验收标准，不写「改进整个代码库」。
- 判断顺序：不做 > 脚本 > 复用已有结果 > 当前对话 > 轻量子代理（见 `references/scripts-and-local-first.md`）。
- 模板见 `templates/task-brief.md`；常见疑问见 `references/faq.md`。

## 异常与降级

| 情况 | 默认处理 | 不要做什么 |
|---|---|---|
| 缺对象/范围/用途/验收 | 一次问 2–4 个带推荐选项的问题 | 逐个挤牙膏式追问 |
| 用户不回答 | 标「等待用户输入」，给一个低成本默认方案 | 擅自扩大范围 |
| 读不到模型倍率或积分明细 | 只输出低/中/高相对成本 | 报具体积分、编价格 |
| 无法写记忆文件 | 在回复里输出交接摘要供用户复制 | 假设已写入 |
| 环境没有子代理 | 给单会话分阶段方案 | 假装已派出 |
| 预计超 30 万 token | 停止，给拆分/降档/放弃三选项 | 先做后报 |
| 批量生成 | 先确认数量、尺寸、风格，先出 1 件样品 | 整批直接开跑 |
| 同一动作连续失败 2 次 | 停止重试，转查根因 | 第 3 次盲目重试 |
| 等待授权/确认/第三方 | 停止轮询，写明等待对象和恢复条件 | 定时轮询自检 |

【官方规则】循环确认时选「终止请求」会进入退费评估（依据见 `references/sources.md`）；本技能不承诺退费。
