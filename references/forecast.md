# 大用量预测与七类浪费

## 大用量预测【经验规则】
粗估折算 token ≈ 读入材料量×2 + 预计输出量×4 + 预计轮数×当前上下文大小（最后一项最易漏）。这是经验估算，不是官方计费公式，只用来分档，不当作精确数字。

| 估算（折算 token） | 做法 |
|---|---|
| < 10 万 | 直接做，写上限 |
| 10–30 万 | 拆成并行块，每块写上限；先让轻量模型抽事实包（不超过 6,000 字） |
| > 30 万 | 先停，给用户拆分/降档/放弃三选项，不先做后报 |

常见大头：整本 PDF/PPT 解析进上下文、资料库全文整篇带入、多轮推理评审、长会话第 N 轮追问、批量图片/视频生成（先确认参数和数量，先出一件）。事后记「预估 vs 实际」，连续 3 次偏差超 2 倍就调系数。

## 七类浪费对照
| 浪费 | WorkBuddy 里的样子 | 对策 |
|---|---|---|
| 过度生产（常见大头） | 需求没问清就派活 | 先澄清四要素 |
| 等待 | 子代理空跑、后台挂着、轮询外部条件 | 停止轮询，写明等待对象 |
| 库存 | 同一数据反复重搜、中间产物囤着 | 结果落盘，同日复用 |
| 搬运 | 上下文越长后续请求带的量越大【环境实测/经验】；大文件整包进上下文 | 会话卫生 + 事实包 |
| 过度加工 | 反复评审、日常任务用最强模型 | 评审分档 |
| 多余动作 | 脚本能干的派 agent；挤牙膏式反问 | 脚本优先 |
| 缺陷返工 | 方向错了重做；批量生成整批返工 | 先出一件确认再批量 |

先问「该不该做、做什么」，再问「怎么省着做」。在错的事上做效率优化，是双重浪费。

## 实测补充【环境实测】2026-11-16 单一环境
- 同一任务两次积分可差 2–4 倍；技能固定开销估计约 +5 千 token/轮（约 +16%），也有 2–4 倍波动。
- 积分按「请求」计，同一轮里并行多做几件事，比拆成多轮便宜（经验推断）。
