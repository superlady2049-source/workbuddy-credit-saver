# 工具与技能按需加载；防返工

## 工具与技能
- 延迟加载的工具不占默认上下文，但加载定义也耗轮次：先精确查名，拿到定义再调用，不要反复搜索。
- 技能是软触发，只在任务匹配时加载；不要为省积分拒绝加载匹配的技能——走错路的返工比一次技能加载贵得多。
- 大文件（PDF/DOCX/PPTX）优先走专用技能的解析通道，不要用通用读取硬读二进制。
- 批量文件操作用命令行并行，不要一个文件一轮对话。
- **连接器/MCP 开销（官方成本文档）：** 每个连接的服务器会把工具定义常驻上下文，空闲也占。定期检查，不用的关掉；命令行场景优先用 gh 等命令行工具代替 MCP。
- **记忆和技能描述也占上下文：** 用户级记忆、技能的 description 每次会话都载入。记忆只写强制规则；描述写触发词，不写长篇介绍。
- **摸文档站先读地图：** 先读 robots.txt / sitemap.xml 拿真实页面清单，再逐页抓；不要凭猜试网址（作者一次核实任务中盲猜路径的无效命中率达 1/3）。

## 防返工四法（官方成本文档，复杂任务的高效工作方式）
1. **计划先行：** 复杂任务先出方案、获批再执行（Plan 模式），避免初始方向错误的昂贵返工。
2. **尽早纠偏：** 发现走错方向立即停（终止请求），不要等它跑完；能回退的用检查点回退。
3. **给验证目标：** 派活时附测试用例、截图或预期输出，让 agent 自我验证。
4. **增量推进：** 写一个文件/模块就测一次，问题在小的时候发现。
