# 脚本优先、本地优先、结果落盘

## 一、这些活一律先写脚本，不派 agent
- 固定网址的榜单/页面抓取：命令行下载加解析，一条命令，零积分（例：规律固定的第三方数据日榜）
- 批量文件改名、转码、整理：循环脚本，不是逐文件一轮对话
- 数据校验、对账、比对：脚本，让 agent 肉眼比对又慢又贵
- 日志统计、计数、排序：grep/awk
- 格式检查、正则匹配

一次写脚本，无限次零积分复用；agent 只读脚本输出的结构化结果（json/csv），只做判断和呈现，不搬运原始数据。**一个活出现第 3 次、步骤一样，就该脚本化。**先让用户认可内容和方向，再固化成脚本。

## 二、本地优先
联网搜索之前，先查本地文件、工作区记忆、资料库、历史对话——很多「搜」其实是「翻」。动手前自问：这数据本机有没有？之前查过没有？

## 三、结果落盘复用
每次取数、分析的结果存成文件（写明日期和口径），同一问题当天再被问到，读文件不重搜。搜过的东西不落盘，等于白搜。数据有时效的，标明截至哪天。

## 四、当前对话替代子代理
一两次搜索/读取就能回答的「帮我查一下 X」，在当前对话里直接做；子代理留给多轮迭代的开放式探索（大项目梳理、需要多轮收敛的调研），并限定它只回传摘要。

## 五、周期任务自动化
「每天/每周帮我取 X」固化成定时任务或本机定时脚本，不靠长会话挂着等。定时任务的提示保持窄上下文、自包含。（定时任务功能以你的实际界面为准。）
